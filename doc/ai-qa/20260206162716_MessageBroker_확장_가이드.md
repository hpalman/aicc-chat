## 개요

`MessageBroker` 인터페이스를 확장하여 다음과 같은 기능을 추가했습니다:

### 개선 전

- 고정된 토픽(`"chat.topic"`)에만 발행 가능
- `ChatMessage` 타입만 지원

```java
messageBroker.publish(chatMessage);  // "chat.topic"에만 발행
```

### 개선 후

- 동적 토픽 이름 지정 가능
- 모든 객체 타입 지원 (제네릭 사용)

```java
// 기본 토픽 사용 (기존 방식, 호환성 유지)
messageBroker.publish(chatMessage);

// 동적 토픽 사용
messageBroker.publish("scheduler.control", schedulerMessage);
messageBroker.publish("custom.topic", customObject);
```

## 코드 변경 내용

### MessageBroker.java

**변경 전**:
```java
public interface MessageBroker {
    void publish(ChatMessage message);
}
```

**변경 후**:
```java
public interface MessageBroker {
    /**
     * 채팅 메시지를 기본 토픽("chat.topic")으로 발행
     */
    void publish(ChatMessage message);

    /**
     * 지정된 토픽으로 객체를 발행
     * 
     * @param topicName Redis Pub/Sub 토픽 이름
     * @param message 발행할 객체 (모든 타입 가능)
     * @param <T> 메시지 객체 타입
     */
    <T> void publish(String topicName, T message);
}
```

### RedisOnlyConfig.java

**변경 전**:
```java
@Bean
public MessageBroker messageBroker() {
    return message -> {
        try {
            message.setTimestamp(LocalDateTime.now());
            String msg = objectMapper.writeValueAsString(message);
            log.info("▷ chat.topic > msg:{}", msg);
            redisTemplate.convertAndSend("chat.topic", msg);
        } catch (Exception e) {
            log.error("Redis Publish Error", e);
        }
    };
}
```

**변경 후**:
```java
@Bean
public MessageBroker messageBroker() {
    return new MessageBroker() {
        private static final String DEFAULT_TOPIC = "chat.topic";

        @Override
        public void publish(ChatMessage message) {
            // 기본 토픽으로 ChatMessage 발행
            publish(DEFAULT_TOPIC, message);
        }

        @Override
        public <T> void publish(String topicName, T message) {
            try {
                // ChatMessage인 경우 타임스탬프 설정
                if (message instanceof ChatMessage chatMessage) {
                    chatMessage.setTimestamp(LocalDateTime.now());
                }

                // 객체를 JSON으로 직렬화
                String msg = objectMapper.writeValueAsString(message);
                log.info("▷ {} > msg:{}", topicName, msg);

                // Redis Pub/Sub으로 발행
                redisTemplate.convertAndSend(topicName, msg);
            } catch (Exception e) {
                log.error("Redis Publish Error - topic: {}, message: {}", topicName, message, e);
            }
        }
    };
}
```

## 기존 코드 호환성

### ✅ 완전 호환

기존 코드는 **수정 없이 그대로 동작**합니다:

```java
// 기존 코드 (변경 불필요)
messageBroker.publish(chatMessage);
```

**동작**:
1. `publish(ChatMessage)` 메서드 호출
2. 내부적으로 `publish("chat.topic", chatMessage)` 호출
3. 기본 토픽으로 발행 (기존과 동일)

### 마이그레이션 예시

**기존 코드**:
```java
ChatMessage message = ChatMessage.builder()
    .roomId("room-123")
    .sender("홍길동")
    .message("안녕하세요")
    .build();

messageBroker.publish(message);  // ✅ 그대로 동작
```

**새로운 기능 사용**:
```java
// 동일한 메시지를 다른 토픽으로도 발행 가능
messageBroker.publish("chat.topic", message);      // 기본 토픽
messageBroker.publish("chat.archive", message);   // 아카이브 토픽
```

## 주의사항

### 1. ChatMessage 타임스탬프 자동 설정

- `publish(ChatMessage)` 또는 `publish(topic, ChatMessage)` 호출 시
- `ChatMessage`인 경우 자동으로 `setTimestamp(LocalDateTime.now())` 호출
- 다른 타입의 객체는 타임스탬프 설정 안 함

### 2. JSON 직렬화

- 모든 객체는 `ObjectMapper`를 사용하여 JSON으로 직렬화됩니다
- 직렬화 가능한 객체만 발행 가능 (Jackson 어노테이션 지원)

### 3. 토픽 이름 규칙

- Redis 채널 이름은 문자열입니다
- 관례적으로 소문자와 점(.)을 사용: `"chat.topic"`, `"scheduler.control"`
- 특수문자 사용 가능하지만 일관성을 위해 제한하는 것을 권장

### 4. 에러 처리

- 직렬화 실패 시 `log.error()`로 로그 기록
- 예외가 발생해도 애플리케이션은 계속 실행됨
- 중요한 메시지는 재시도 로직을 별도로 구현 권장

### 5. Redis 채널 구독

- 새로운 토픽을 사용하려면 해당 토픽을 구독하는 리스너가 필요합니다
- `RedisMessageListenerContainer`에 리스너를 추가해야 메시지를 수신할 수 있습니다
