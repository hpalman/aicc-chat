## 개요

고객이 "상담 종료" 버튼을 클릭하여 `/api/customer/chatend` API를 호출할 때, Redis에서 관련된 모든 키를 삭제하도록 개선했습니다.

### 개선 전 문제점

- 채팅방 상태만 CLOSED로 변경하고 실제 Redis 키는 삭제하지 않음
- `chat:room-info:{roomId}`, `chat:room-member:{roomId}`, `chat:rooms`, `chat:user-customers:{userId}` 키가 남아있어 메모리 누수 발생 가능
- 상담원 화면에 종료된 방이 계속 표시될 수 있음

### 개선 후

- 고객 상담 종료 시 관련된 모든 Redis 키를 완전히 삭제
- 메모리 누수 방지 및 데이터 정합성 확보
- 상담원 화면에서 종료된 방이 즉시 제거됨

|---------|------|------|

## 삭제되는 Redis 키 목록

### 1. 채팅방 관련 키 (roomRepository.deleteRoom())

#### `chat:rooms` (Set)
- **동작**: `SREM chat:rooms {roomId}`
- **설명**: 전체 방 목록 인덱스에서 해당 roomId 제거

#### `chat:room-info:{roomId}` (Hash)
- **동작**: `DEL chat:room-info:{roomId}`
- **설명**: 방 메타데이터 Hash 전체 삭제
- **포함 필드**:
  - `name`: 방 이름
  - `createdAt`: 생성 시간
  - `lastActivity`: 마지막 활동 시간
  - `mode`: 방 상태 (BOT/WAITING/AGENT/CLOSED)
  - `assignedAgent`: 배정된 상담원 이름

#### `chat:room-member:{roomId}` (Set)
- **동작**: `DEL chat:room-member:{roomId}`
- **설명**: 방 멤버 목록 Set 전체 삭제
- **포함 멤버**: 고객 ID, 상담원 ID 등

### 2. 고객 관련 키 (customerAuthService.logout())

#### `chat:user-customers:{userId}` (Hash)
- **동작**: `DEL chat:user-customers:{userId}`
- **설명**: 고객 정보 Hash 전체 삭제
- **포함 필드**:
  - `userName`: 고객 이름
  - `userId`: 고객 ID
  - `loginTime`: 로그인 시간
  - `roomId`: 채팅방 ID
  - `sessionId`: WebSocket 세션 ID
  - `companyId`: 회사 ID

```java
@Override
public void deleteRoom(String roomId) {
    log.info("▶▶▶ roomId:{}", roomId);
    Boolean b;
    
    // chat:rooms에서 roomId 제거
    redisTemplate.opsForSet().remove(CHAT_ROOMS_KEY, roomId);
    
    // chat:room-member:{roomId} Set 삭제
    b = redisTemplate.delete(Constants.ROOM_MEMBERS_KEY_PREFIX + roomId);
    if (!b) { 
        log.error("delete room:mems:{} failed.", roomId); 
    }
    
    // chat:room-info:{roomId} Hash 삭제
    b = redisTemplate.delete(ROOM_KEY_PREFIX + roomId);
    if (!b) { 
        log.error("delete chat:room:{} hash failed.", roomId); 
    }
}
```

## 주의사항

### 1. 상담원이 배정된 경우

- 고객이 상담 종료하면 상담원에게도 알림 메시지가 전송됩니다.
- 채팅방이 완전히 삭제되므로 상담원도 더 이상 해당 방에 접근할 수 없습니다.

### 2. 동시성 고려

- `deleteRoom()` 메서드는 원자적으로 실행되지만, 여러 요청이 동시에 들어올 경우를 대비해 방 상태를 먼저 확인하는 것이 좋습니다.
- 현재 구현에서는 `roomRepository.findRoomById()`로 방 존재 여부를 확인한 후 삭제합니다.

### 3. 데이터 복구 불가

- Redis 키를 삭제하면 복구할 수 없습니다.
- 중요한 데이터는 PostgreSQL에 저장되므로, 필요시 DB에서 조회할 수 있습니다.
