# 스케줄러 동적 설정 API 개선

> **작성일**: 2026-02-02  
> **목적**: `/api/cleanup/scheduler/start` API 호출 시 `idle-timeout`과 `check-interval` 값을 동적으로 설정할 수 있도록 개선  
> **범위**: RoomCleanupController, RoomCleanupSchedulerManager, RoomCleanupService

---

## 📋 변경 사항

### 1. SchedulerStartRequest DTO 추가

**파일**: `src/main/java/aicc/chat/dto/SchedulerStartRequest.java`

```java
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class SchedulerStartRequest {
    /**
     * 유휴 타임아웃 시간 (밀리초)
     * null이면 기본값 사용
     */
    private Long idleTimeout;

    /**
     * 정리 작업 실행 주기 (밀리초)
     * null이면 기본값 사용
     */
    private Long checkInterval;
}
```

### 2. RoomCleanupController 수정

**파일**: `src/main/java/aicc/chat/controller/RoomCleanupController.java`

- `start()` 메서드에 `@RequestBody(required = false) SchedulerStartRequest request` 파라미터 추가
- RequestBody가 없어도 동작하도록 `required = false` 설정
- 전달된 값이 있으면 사용하고, 없으면 기본값 사용

```java
@PostMapping("/start")
public ResponseEntity<Map<String, Object>> start(@RequestBody(required = false) SchedulerStartRequest request) {
    Long idleTimeout = request != null ? request.getIdleTimeout() : null;
    Long checkInterval = request != null ? request.getCheckInterval() : null;
    
    boolean started = schedulerManager.start(idleTimeout, checkInterval);
    SchedulerStatus status = schedulerManager.getStatus();
    return ResponseEntity.ok(Map.of(
            "message", started ? "스케줄러가 시작되었습니다." : "스케줄러가 이미 실행 중입니다.",
            "status", status
    ));
}
```

### 3. RoomCleanupSchedulerManager 수정

**파일**: `src/main/java/aicc/chat/service/RoomCleanupSchedulerManager.java`

- `start(Long idleTimeout, Long checkInterval)` 메서드 오버로드 추가
- 기존 `start()` 메서드는 기본값을 사용하도록 유지
- 동적으로 전달된 값으로 스케줄러 설정 업데이트

```java
public synchronized boolean start(Long idleTimeout, Long checkInterval) {
    if (scheduledFuture != null && !scheduledFuture.isCancelled()) {
        log.info("cleanupIdleRooms scheduler is already running.");
        return false;
    }
    
    // 동적 값 설정
    if (idleTimeout != null) {
        roomCleanupService.setIdleTimeout(idleTimeout);
        log.info("Idle timeout updated to: {} ms", idleTimeout);
    }
    
    long intervalToUse = checkInterval != null ? checkInterval : checkIntervalMs;
    if (checkInterval != null) {
        this.checkIntervalMs = checkInterval;
        log.info("Check interval updated to: {} ms", checkInterval);
    }
    
    Runnable task = () -> {
        lastRunTime = Instant.now();
        roomCleanupService.cleanupIdleRooms();
    };
    scheduledFuture = taskScheduler.scheduleAtFixedRate(task, Duration.ofMillis(intervalToUse));
    log.info("cleanupIdleRooms scheduler started (interval: {} ms).", intervalToUse);
    return true;
}
```

### 4. RoomCleanupService 수정

**파일**: `src/main/java/aicc/chat/service/RoomCleanupService.java`

- `idleTimeout`과 `checkInterval` 필드를 `volatile`로 변경하여 동시성 안전성 확보
- `setIdleTimeout(long idleTimeout)` 메서드 추가
- `setCheckInterval(long checkInterval)` 메서드 추가

```java
@Value("${app.chat.cleanup.idle-timeout:600000}")
private volatile long idleTimeout; // 유휴 타임아웃 (기본값: 10분)

@Value("${app.chat.cleanup.check-interval:60000}")
private volatile long checkInterval; // 정리 작업 주기 (기본값: 1분)

public void setIdleTimeout(long idleTimeout) {
    this.idleTimeout = idleTimeout;
    log.info("Idle timeout set to: {} ms", idleTimeout);
}

public void setCheckInterval(long checkInterval) {
    this.checkInterval = checkInterval;
    log.info("Check interval set to: {} ms", checkInterval);
}
```

## 🔧 사용 방법

### 기본값으로 시작 (기존 방식)

```bash
curl -X POST http://localhost:28070/api/cleanup/scheduler/start
```

또는 빈 body로 요청:

```bash
curl -X POST http://localhost:28070/api/cleanup/scheduler/start \
  -H "Content-Type: application/json" \
  -d '{}'
```

### 동적 값 설정하여 시작

```bash
curl -X POST http://localhost:28070/api/cleanup/scheduler/start \
  -H "Content-Type: application/json" \
  -d '{
    "idleTimeout": 300000,
    "checkInterval": 30000
  }'
```

**설명**:
- `idleTimeout`: 300000ms (5분) - 유휴 타임아웃 시간
- `checkInterval`: 30000ms (30초) - 정리 작업 실행 주기

### 부분 설정 (하나만 설정)

```bash
# idleTimeout만 설정
curl -X POST http://localhost:28070/api/cleanup/scheduler/start \
  -H "Content-Type: application/json" \
  -d '{
    "idleTimeout": 900000
  }'
```

```bash
# checkInterval만 설정
curl -X POST http://localhost:28070/api/cleanup/scheduler/start \
  -H "Content-Type: application/json" \
  -d '{
    "checkInterval": 120000
  }'
```

## ⚠️ 주의사항

1. **스케줄러 재시작 필요**: 이미 실행 중인 스케줄러의 설정을 변경하려면 먼저 `/api/cleanup/scheduler/stop`으로 중지한 후 새로운 설정으로 다시 시작해야 합니다.

2. **기본값**: `application.yml`에 설정된 기본값은 다음과 같습니다:
   - `idle-timeout`: 600000ms (10분)
   - `check-interval`: 60000ms (1분)

3. **동시성 안전성**: `volatile` 키워드를 사용하여 멀티스레드 환경에서도 안전하게 동작합니다.

4. **값 검증**: 현재는 값 검증이 없으므로, 음수나 0 같은 잘못된 값이 전달되면 예상치 못한 동작이 발생할 수 있습니다. 필요시 추가 검증 로직을 구현하는 것을 권장합니다.
